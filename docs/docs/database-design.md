# Database Design – Chartered Flight Database Management System

## 1. Introduction

This document describes the proposed database design for the Chartered Flight Database Management System (CFDBMS), developed for the Impact Charter Services (ICS) case study.

The database is intended to provide a centralised structure for managing the company's operational information.

## 2. Database Requirements

The proposed database should support:

- Customer information management.
- Passenger information management.
- Charter flight bookings.
- Aircraft records.
- Pilot and crew records.
- Crew assignments.
- Financial transactions.
- Aircraft maintenance activities.

## 3. Proposed Database Entities

The following entities are proposed for investigation during database design:

| Entity | Purpose |
|---|---|
| Customer | Stores customer details. |
| Passenger | Stores passenger information. |
| Booking | Records charter booking requests. |
| Aircraft | Maintains aircraft information. |
| Pilot | Stores pilot records. |
| Crew | Maintains crew information. |
| Crew Assignment | Records crew allocated to flights. |
| Financial Transaction | Records financial activities. |
| Maintenance | Records aircraft maintenance activities. |

*The final entities and attributes will be confirmed through detailed analysis of the coursework requirements.*

## 4. Relationships

The database design will investigate relationships between:

- Customers and bookings.
- Bookings and passengers.
- Bookings and aircraft.
- Pilots and flight assignments.
- Crew members and assignments.
- Aircraft and maintenance records.
- Bookings and financial transactions.

## 5. Database Design Principles

The proposed design will consider:

- Primary keys.
- Foreign keys.
- Entity relationships.
- Referential integrity.
- Data validation.
- Database normalisation.
- Reduction of unnecessary data duplication.
